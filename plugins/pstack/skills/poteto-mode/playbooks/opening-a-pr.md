### Opening a PR

Invoked at the end of every other playbook.

Work from a git worktree off trunk, and keep unrelated work out of it. Rebase into small, landable commits. Run `/deslop` over the diff before commit. Before the first push, run every CI job's `run:` command locally at its pinned version, tests and builds included, and run a missing binary through `npx` or `bunx` at the pinned version rather than skip it. Before you commit, merge, or deploy from a worktree, list the live agents and stop every one that holds it, including grandchildren you never launched. Confirm each stop, then run `git status` and read the tree you are about to ship.

Title: `type(scope): subject`, naming a real symbol when one carries the change. Body: a one-minute briefing under 40 lines with these `##` headings in order, dropping empty ones: `## Why`, `## What changed`, `## Scope`, `## Tradeoffs` (only rejected alternatives a reviewer would otherwise ask about), `## Blast Radius`, `## Verification`. In `## Scope`, name each follow-up's owner, which is an open PR, an issue, or the user. When users get the change only through a later release or deploy, tell the user in your reply that merging alone ships nothing. Write `## Blast Radius` from the list of consumers that the **blast-radius** skill builds, not from what you tested. In `## Verification`, name each CI job you could not run locally. Read a body you will write back with `gh pr view <pr> --json body --jq .body 2>/dev/null`, because `gh` prints a `hint:` line on stderr, some runtimes merge stderr into stdout, and the line would reach the squash commit.

Stack follow-ups by base branch. Open PRs ready, through the run's PR tool with `draft: false`. Without one, use `gh pr create` without `--draft`, or `origin pr create --status open` when Origin's CLI resolves the repository. Opening a PR does not start a babysit.
